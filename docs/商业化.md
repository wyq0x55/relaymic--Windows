## 〇、竞品空档查证（2026-08-17 实测）

**TeamViewer 没有麦克风穿透**：官方社区确认远程会话用的是远程机器自己的麦克风，
本地麦克风传不过去；并存在专门的功能请求帖（"Microphone Transmission"）——
请求帖本身就是真需求的公开证据。

**市场边界**：Windows→Windows 有官方免费方案（微软 RDP 自带麦克风重定向
`audiocapturemode:i:1`），**不打这个方向**；但该方案到 Mac 就断了 ——
Mac 作为被控端没有 RDP 服务，全生态无官方方案。

| 方向 | 现状 | 定位 |
| --- | --- | --- |
| Windows → Windows | RDP 官方免费支持 | 不做 |
| 任何设备 → **Mac** | TeamViewer/AnyDesk/ToDesk 全缺失 | **主战场，空档实锤** |

## 一、产品定位

**一句话**：接收端装在 Mac 上，之后任何设备打开一个网页，就是那台 Mac 的麦克风。

- 发送侧零安装、全平台：Windows / MacBook / 手机 / 平板 / Linux，浏览器打开即用
- 核心场景是**异地远程**（人在 A 地，Mac 在 B 地）——远程桌面软件（ToDesk/向日葵/RustDesk）
  对 Mac 方向的麦克风穿透普遍缺失，这是真实空档
- Apple 永远不会做 Windows→Mac 的跨生态方向；iPhone→Mac 已被官方"连续互通"免费收编，
  所以主打场景避开手机、聚焦桌面跨设备与远程

## 二、评分结论（10 项评分卡）

两轮评分的关键差异是场景假设：

| 场景假设 | 总分 | 结论 |
| --- | --- | --- |
| 同房间多机切换（初评）| 12/20 | 不值得做 —— 对手是一个 ¥50 的 USB 麦克风 |
| **异地远程（纠正后）** | **16/20** | 过 14 分线，值得推进验证 —— 麦克风插不到千里之外，无物理替代 |

剩余短板（各 1 分）：
- 第 3 购买理由：重复性+即时意愿硬（无替代），但无风险/焦虑成分
- 第 5 付费意愿：非"不解决会翻车"的损失驱动
- 第 7 护城河：迁移成本低；真实威胁是远控大厂随手加麦克风穿透功能。
  应对：不绑定任何远控软件 + 音质专业性（三采样点诊断）做差异化

填空题：**远程使用 Mac（远控/托管 Mac mini）的语音输入用户，在异地对远程 Mac
说话时，愿付 ¥15~30/月 或 ~$19 买断，解决远程桌面没有麦克风穿透的问题。**

## 三、行动方案：投流测试（两周，预算封顶 ¥1000）

产品不用动，原型已够 demo。

1. **落地页**
   - 主张："给你的远程 Mac 一个麦克风"
   - 演示 GIF：Windows 说话 → 远程 Mac 微信语音输入出字（这个画面就是全部卖点）
   - 转化动作：预售 $19 买断（最硬）或留邮箱
2. **只投搜索词，不投信息流**（窄人群在信息流圈不出来；搜索广告顺便验证搜索量）
   - 英文：remote desktop microphone mac / use microphone on remote mac
   - 中文：向日葵 麦克风 / todesk 语音输入 / 远程桌面 麦克风
3. **过线标准（现在定死，防止事后靠感觉）**
   - 落地页转化（点击→邮箱/预售）> 5%
   - 单邮箱成本 < ¥20
   - 预售 ≥ 5 单（有这条其他都可忽略）
4. **纪律**：预算封顶就是封顶。数据不过线时"再加点预算试试"是沉没成本在说话。

### 投放关键词库（英文 + 西班牙语）

英文核心意图：
`remote desktop microphone mac` / `use microphone over remote desktop mac` /
`microphone passthrough remote desktop` / `remote mac microphone`

英文竞品场景（痛点最具体，转化预期最好）：
`parsec microphone mac` / `rustdesk microphone` / `anydesk microphone not working mac` /
`teamviewer microphone remote mac` / `teamviewer microphone transmission`（功能请求原词）/
`jump desktop microphone`

英文功能描述：
`use phone as microphone for mac` / `browser microphone to mac` /
`virtual microphone mac remote` / `voice input remote mac` / `dictation on remote mac`

西班牙语核心：
`micrófono escritorio remoto mac` / `usar micrófono en escritorio remoto` /
`micrófono remoto mac` / `pasar micrófono por escritorio remoto`

西班牙语竞品场景（西语市场 AnyDesk/TeamViewer 占有率高）：
`anydesk micrófono no funciona` / `teamviewer micrófono mac` / `anydesk micrófono mac`

西班牙语功能描述（地区用词差异，两版都测）：
`usar celular como micrófono para mac`（拉美）/ `usar móvil como micrófono mac`（西班牙）/
`micrófono virtual mac` / `dictado por voz mac remoto`

判断原则：带 use/usar/not working/no funciona/how to 的是任务词（有生意），
纯名词组合可能是围观词；竞品词的搜索量是"空档真实性"的直接证据；
量小正常（niche 品类），看 CPC 低 + 意图硬。

## 四、路线 A：过线 → 闭源商业化（全球，订阅制）

**全球化决策（2026-08-17）**：主打英文市场。
- 增：全产品 i18n 英文优先（GUI/网页/报错/文档，~1 周）；GDPR 隐私政策
  （亮点写法："音频点对点传输，不经我们服务器存储"）
- 减：ICP 备案、微信/支付宝、国内主体全部推后
- 定：**订阅 $4.99/月 或 $49/年**（年付主推），7 天全功能试用，含官方中继流量；
  支付走 Paddle / LemonSqueezy（MoR 兜全球税务）；区域 PPP 折扣价
- 为什么订阅而非买断：投流 CAC $50~150，买断 $19 打不正；且小白用户
  人人要走官方中继（无 Tailscale），持续成本真实存在，订阅正当
- 必做工程（4~6 周）：配对码+官方信令/中继、签名公证一键 .pkg、
  菜单栏 App、支付+license、无人陪跑级报错与自检、落地页+FAQ

（以下为开源路线下的买断方案，仅当走路线 B 后再商业化时参考）


模式：**代码可后续开源获客，销售走"官方构建收费"**（Aseprite/Ardour 模式：
会自己编译的人本来不付钱，付钱的人买"别让我折腾"）。

| | 免费 | 付费（$9.9~19.9 买断）|
| --- | --- | --- |
| Windows exe / 网页发送端 | ✓（无安装负担）| — |
| Mac 接收端 | 自己编译+脚本+brew | **双击 .pkg 一键装完即在线** |

付费版体验清单（工程 3~5 天）：
1. 一键安装器：引导安装 BlackHole（调官方 pkg，**不捆绑** —— 不构成 GPL 分发，
   免谈商业授权）→ 自动配置 launchd/权限 → 装完即在线
2. 菜单栏小图标：连接状态/发送端名/电平一眼可见，监控页入口
3. 自动更新（Sparkle）
4. 签名+公证：无"无法验证开发者"弹窗（这条本身就是付费理由）
5. 干净卸载

成本：Apple 开发者账号 $99/年。收入预期要诚实：**咖啡钱量级**
（同类开源工具官方构建典型月入几十~几百美元）。

## 五、路线 B：不过线 → 开源名片

价值不走"卖钱"栏，但账是正的：
- 自用价值已兑现（三台机器日常在用）
- GitHub star/个人品牌，对 SaaS 主业长期背书
- 工程沉淀：整条语音输入链路 know-how
- 可定位为 Tailscale 生态工具（"voice input over your tailnet"）——人群精准、
  零额外开发、Tailscale 社区是免费曝光位

开源前必做（安全）：
1. **换 TURN 密码**（服务器上改——旧密码在 git 历史里，删文件没用）
2. **新开公开仓库、不带 git 历史**
3. 清洗硬编码：deploy-fleet.sh 的 TURN 默认值、docs/ 里真实 IP、
   GUI 代码里写死的默认地址

开源前必做（可用性，判据"陌生人 30 分钟跑通"）：
4. README 陌生人视角重写（中英双语）
5. 验证无 TURN 默认路径（同 tailnet/局域网零配置可用），TURN 写成
   "对称 NAT 才需要 + coturn 自建三步"
6. GitHub Release 流程（tag → CI 挂二进制，Actions artifact 要登录不可用）
7. LICENSE 选 MIT（BlackHole 用户自装、不分发，开源形态无 GPL 问题）

加分：GUI+监控页截图、排障故事文章（HN/Reddit 的免费流量）。

## 五点五、成本与收费对齐（重要澄清）

"买断制无持续成本"需要拆开：信令去中心（零）、STUN 公共免费（≈零）、
**TURN 中继是唯一有账单的环节**（全量音频过服务器）。
- 开源/买断路线：TURN 不含 —— tailnet 用户默认配置下 Tailscale 候选
  自带兜底（DERP），无需我们的中继；需要官方中继者单独可选订阅
- 投流/订阅路线：小白用户必经官方中继 → 中继成本摊进订阅，结构自洽

## 六、已否决的方向（记录原因，防止绕回来）

| 方向 | 否决原因 |
| --- | --- |
| 同房间多机场景商业化 | 对手是 ¥50 USB 麦克风，购买理由塌 |
| 配对码 + 托管信令/TURN 订阅（**仅路线 B 下否决**）| 开源/tailnet 路线无必要；但在路线 A（全球投流订阅）中是必做核心 |
| Windows 原生 exe 作为主力形态 | 网页端已补齐多台同收/自动发现/编码控制；唯一差异是常驻性。exe 冻结不删，维护面减半 |
| 手机→Mac 主打 | 被 Apple 连续互通免费收编 |
